# 点击"暂停"失效的几种网站 & 统一解法

> 记录 1.30–1.46 期间真实遇到的五类问题，以及现在统一在脚本里的处理方式。
> 以后遇到新站点，先按这张表对号入座，不需要再逐个试错。

## 一、问题分类（按根因，不按网站）

| # | 根因 | 典型表现 | 判定方法 | 现在的处理 |
|---|---|---|---|---|
| A | **脚本自己的自动播放循环**把暂停的视频重新拉起 | 暂停后 1.5 秒左右又播 | 关掉脚本就正常 | 用户主动暂停后，**本页自动播放整体停手**（`__vaUserPausedOnce`） |
| B | **脚本的点击兜底**与站点重复切换 | 点暂停后立刻回到播放 | 站点在 `pointerdown` 就切换，脚本在 `click`+80ms 又补一刀 | **完全不接管点击**，播放/暂停 100% 交给站点 |
| C | **悬停自动播放**在你暂停后触发 | 暂停后鼠标一动又播 | 鼠标停在视频上 | 暂停后 3 秒内不触发；悬停需停留 700ms；悬停内部的暂停/播放不计入判断 |
| D | **站点播放器自己在暂停后调用 play()** | 暂停后 1~2 秒自动播放 | 关掉脚本也这样 → 站点行为 | 暂停瞬间**拦截该视频的 `play()`**（返回已完成 Promise），站点调用无效 |
| E | 站点 **高频重复调用 play()** | 画面快速"播一下停一下"闪烁、声音断续 | 肉眼可见抖动 | 同 D，拦截后不再与站点拉锯，画面安静停在暂停 |

## 二、统一实现：PauseShield

```
暂停事件(非脚本发起)
   → PauseShield.protect(video)
        · 记录 __vaOrigPlay，把 video.play 换成空实现
        · video.pause()
        · 标记本页"用户已暂停" → 自动播放循环/观察器全部停手
用户输入(pointerdown / keydown / touchstart) 或 我方主动播放
   → PauseShield.release()
        · 恢复所有被拦截的 play()
        · 清除"用户已暂停"标记
```

要点：
1. **不判断网站域名**，只判断"这个视频此刻发生了什么"
2. **拦截而不是对抗**：不反复 pause（那会产生闪烁），而是让站点的 play 调用失效
3. **用户优先**：只要有任何输入就解除，不会把用户主动播放压回去
4. 悬停切换、快捷键、音量 HUD 都不受影响

## 三、新站点排查顺序（3 步）

1. **关掉脚本**试一次：还这样 → 站点自身行为（走 D/E 分支，用拦截）
2. 关掉就正常 → 看是"暂停后 0.5~2 秒自动播"（A/C）还是"立刻回到播放"（B）
3. 对应的开关：
   - A：`__vaUserPausedOnce`
   - B：脚本不接管点击
   - C：悬停 3 秒保护 + 700ms 停留
   - D/E：`PauseShield.protect`
