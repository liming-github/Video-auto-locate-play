v1.56.0 更新说明

【修复】没有视频的页面不再被自动定位/滚动（同时不影响有视频页面的自动定位）

一、之前为什么修不好（反复失败的原因）
- 旧兜底逻辑把「页面上任意大 iframe」和「面积最大的 div」都当成播放器，
  导致列表页、文章页、GitHub/Greasyfork 这类没有视频的页面也会被滚一下。
- 上一版（1.54）尝试修复时，用了「页面里有 <video> 就直接返回」的判据，
  结果把「有视频但还没播起来 / 被浏览器拦截」的页面也一起砍掉，
  造成「非视频不滚了，视频也不滚了」。

二、这一版的判据（只看页面事实，不用域名白名单）
按下面顺序，命中就定位，全都不命中就一步都不滚：
1. 页面里有可见 <video>（含同源 iframe / Shadow DOM 内）→ 直接定位到它，
   不管它是否已经开始播放（关键：不再依赖「播起来才滚」）。
2. 有播放器容器（.ql-video / .xgplayer / .dplayer / .video-js / .plyr / #player 等），
   且容器内部确实有 <video> 或带 src 的 <iframe> → 定位到该容器。
3. 有「带明确视频信号」的 iframe（src 命中 youtube/embed、vimeo、bilibili、
   player./video./.mp4/m3u8 等）→ 定位到该 iframe（跨域播放器常见）。
4. 以上都没有 → 一步都不滚。

三、明确移除的两个误判来源
- 不再把「任意 iframe」当播放器（广告 / 地图 / 评论嵌入 iframe 不会误滚）。
- 不再把「面积最大的 div」当播放器（文章正文不会再被滚）。

【测试】新增 5 项自动化用例，覆盖：无视频页面不滚、裸 video（暂停 + 播放被拒）仍定位、
零尺寸视频容器定位、视频信号 iframe 定位、广告 iframe 不滚，全部通过。
