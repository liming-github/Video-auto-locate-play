v1.56.1 更新说明

【修复】91porna 等「播放器懒加载」站点自动定位失效（v1.56.0 引入的回归）

一、原因
v1.56.0 修复「无视频页面误滚动」时，要求播放器容器内部必须有 <video> 或带 src 的 iframe 才算数。
但 91porna 这类站点把播放器做成「懒加载」：页面里先放一个空壳容器
（<div class="ql-video"><div data-playback-post>…</div></div>），
要等滚动到它进入视口后，才由 IntersectionObserver 动态创建 <video>（xgplayer + HLS）。

于是出现鸡生蛋问题：定位要滚动容器，但容器要等被滚动后才出现 <video>，
v1.56.0 的判据「容器内必须有 video/iframe」永远不满足，自动定位就不触发。

二、修法
把播放器容器分成两档：
- 强信号（.ql-video / .xgplayer / .dplayer / .art-video-player / .video-js / .plyr）：
  这些类名几乎只代表播放器，**即使此刻还没注入 <video> 也直接定位**（懒加载也认）。
- 弱信号（#player / .player / [class*="video-*"]）：
  类名可能泛用，仍要求内部确有 <video> 或带 src 的 iframe 才算（避免误滚）。

这样既恢复了懒加载站点的定位，又保留了「无视频页面不滚」的保护。

三、验证
- 真实浏览器（Chrome headless + CDP）打开 91porna 该页：scrollY 自动滚到 4136，
  站点懒加载随即创建出 696×392 的 HLS 播放器（blob 源），定位一次完成。
- 新增 3 项 jsdom 用例（空 .ql-video 定位 / 空 .player 不滚 / .player 内有 video 定位）全过；
  原有 5 项「无视频不滚」用例仍全过。
